# NAIOSH Intelligence — الخادم والنظام الكامل (المرحلة الأولى)

يحتوي هذا المجلد على **النظام كاملًا**:

- **الواجهة:** كل شاشات DIA-01 → DIA-24.
- **الخادم (الباك إند):** نظام دخول وصلاحيات، وبيانات مشتركة بين كل المستخدمين، ورفع ملفات وفيديو حقيقي، وسجل قرارات، وسجل تدقيق محمي من التعديل.

النظام جاهز للرفع على دومين.

| تقدّم كل مستخدم | مكان المستخدم في رحلة الاستشارة واختياراته تُحفظ في حسابه وتظهر له على أي جهاز. |
| الأمان | ترويسات أمان كاملة (CSP، HSTS، منع التضمين)، وحماية من طلبات المواقع الأخرى (CSRF). كلمات المرور مشفّرة بـ scrypt. الملفات تُخزَّن خارج مجلد الموقع ولا تُفتح إلا لمن يملك الصلاحية. |

> **ملاحظة صريحة:** نتائج «نتائج التحليل الفعلية» محسوبة فعلًا من بيانات الملف المرفوع، وشروحاتها مولّدة من الأرقام بقواعد ثابتة (دون ذكاء اصطناعي). أما شاشات رحلة الاستشارة النموذجية (CNS-001) وإجابات «اسأل نايوش» فما زالت **محاكاة توضيحية**؛ ربط نموذج لغوي لكتابة الشروح وربط مصادر بيانات المنظمة مباشرة هو **المرحلة الثانية** (انظر آخر الملف).

## الرفع على دومين (الطريقة الموصى بها: Docker)

### ما تحتاجه
1. **خادم VPS:** مثل DigitalOcean أو Hetzner أو AWS Lightsail أو Contabo، بنظام Ubuntu 22.04 أو 24.04. يكفي 2GB رام و40GB مساحة، والمساحة تزيد حسب حجم الفيديوهات.
2. **دومين أو نطاق فرعي:** مثل `app.naiosh.com`.

### الخطوات
1. **اربط الدومين بالخادم:** من لوحة الدومين أضف سجل `A` يشير إلى عنوان IP الخادم، وأضف سجلًا لـ `www` إن رغبت. انتظر حتى يعمل الربط (من دقائق إلى ساعة).
2. **ثبّت Docker على الخادم:**
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. **انسخ مجلد المشروع إلى الخادم:** مثلًا إلى `/opt/naiosh`، عبر git أو `scp`.
4. **جهّز الإعدادات:**
   ```bash
   cd /opt/naiosh
   cp .env.example .env
   nano .env      # اكتب الدومين وبريد وكلمة مرور مدير النظام الأول
   ```
5. **شغّل النظام:**
   ```bash
   docker compose up -d --build
   ```
6. **افتح الموقع:** `https://app.naiosh.com`. شهادة HTTPS تُصدر وتتجدد تلقائيًا. ادخل بحساب المدير، ثم غيّر كلمة المرور من «حسابي».

افتح المنفذين 80 و443 في جدار حماية الخادم إن كان مفعّلًا: `ufw allow 80,443/tcp`.

### أوامر مفيدة
```bash
docker compose logs -f app          # متابعة سجل الخادم
docker compose restart app          # إعادة تشغيل
docker compose up -d --build        # بعد أي تحديث للكود
docker compose exec app node scripts/create-admin.js admin@company.com "NewPass2026" "اسم المدير"   # إنشاء مدير أو استعادة الدخول
```

### النسخ الاحتياطي (مهم)
كل البيانات محفوظة في مجلد `/data` داخل الحاوية: قاعدة البيانات `naiosh.db` ومجلد `uploads` للمرفقات.
```bash
docker compose exec app node scripts/backup.js /data/backups      # نسخة آمنة أثناء التشغيل
docker run --rm -v naiosh_naiosh-data:/data -v $PWD:/out alpine tar czf /out/naiosh-backup.tgz -C /data .   # نسخ كل شيء لملف
```
يُنصح بجدولة النسخ يوميًا عبر `crontab` ونقل الملف خارج الخادم.

### بدون Docker (اختياري)
ثبّت Node.js 22.13 أو أحدث وCaddy على الخادم، ثم انسخ المشروع إلى `/opt/naiosh`:
```bash
npm run build:frontend
sudo cp deploy/naiosh.service /etc/systemd/system/ && sudo systemctl enable --now naiosh
sudo cp deploy/Caddyfile.host /etc/caddy/Caddyfile   # بعد كتابة دومينك فيه
sudo systemctl reload caddy
```

## التشغيل على جهازك للتجربة
```bash
ADMIN_EMAIL=admin@test.local ADMIN_PASSWORD=AdminPass2026 node src/server.js
# ثم افتح http://localhost:3000
npm test        # اختبارات الخادم (12 اختبارًا)
```
لا يحتاج المشروع `npm install`: كل شيء مبني على Node.js وقاعدة SQLite المدمجة فيه.

## تعديل الواجهة
الواجهة مقسّمة إلى أجزاء في `frontend/src/`، وكل جزء ملف مستقل:

| الملف | المحتوى |
|---|---|
| `01_head.html` | الألوان والخطوط |
| `02_config.html` | المحتوى الافتراضي |
| `03_core.html` | القائمة الجانبية والأيقونات |
| `04`–`08` | الشاشات |
| `09_server.html` | الربط بالخادم: الدخول، المستخدمون، صندوق الطلبات |

بعد أي تعديل:
```bash
npm run assemble:frontend
```

## واجهة البرمجة (API) — للمطورين
جميع الطلبات التي تغيّر البيانات تحتاج الترويسة `X-Naiosh: 1`.

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/api/auth/login` · `/api/auth/logout` · `/api/auth/password` | الدخول والخروج وتغيير كلمة المرور |
| GET | `/api/auth/me` | المستخدم الحالي وصلاحياته |
| GET/PUT | `/api/config` | محتوى المنظومة (التعديل للمدير) |
| GET · POST | `/api/config/versions` · `/api/config/versions/:id/restore` | نسخ الإعدادات واسترجاعها |
| GET/PUT | `/api/state` | تقدّم المستخدم |
| POST | `/api/uploads` | رفع ملف خام (`X-File-Name`, `X-Upload-Kind: video\|file`) |
| GET/POST | `/api/requests` | طلبات التحليل |
| GET/PATCH | `/api/requests/:id` | تفاصيل الطلب، تغيير الحالة |
| GET | `/api/files/:id` | تنزيل المرفق (`?inline=1` لتشغيل الفيديو) |
| GET/POST | `/api/decisions` | سجل القرارات |
| GET/POST | `/api/audit` · GET `/api/audit/verify` | سجل التدقيق والتحقق من سلامته |
| GET/POST/PATCH | `/api/users` · `/api/users/:id` | إدارة المستخدمين |
| GET | `/api/health` | فحص حالة الخادم |

## المرحلة الثانية (مقترحة)

1. **ذكاء اصطناعي حقيقي في «اسأل نايوش»:** إجابات من بيانات المنظمة ووثائقها، مع ذكر المصدر ومستوى الثقة.
2. **تحليل الملفات المرفوعة تلقائيًا:** كل الصيغ، مع فحص الجودة وعقد البيانات.
3. **موصلات الأنظمة:** ERP وHR وCRM وLMS.
4. **إشعارات بالبريد:** عند استلام الطلب وتغيير حالته.
5. **نقل التخزين إلى PostgreSQL وS3:** عند كبر حجم الاستخدام أو تعدد المنظمات. الكود مفصول في `src/db.js` لتسهيل هذا الانتقال.
